# DECISIONS

Every judgement call, one line each, with reasoning. Newest at the bottom of each lot.

## Lot 0 — Discovery

- **Restored the deleted working tree rather than treating the empty tree as intent.** All 26 tracked files were deleted unstaged while `HEAD` was intact, and a stray `index.njk copy` remained — the signature of a file-manager mishap, not a deliberate wipe. Rebuilding from nothing would also have made Lots 0 and 2 incoherent, since both assume existing pages to audit and remediate. Confirmed with the user before acting.
- **Created `build/phase-0-1` from `main` @ `e66b3a8`** as `CLAUDE.md` requires. All work is on this branch; `main` is untouched.
- **Installed `node_modules` and Playwright as part of Lot 0, before writing the discovery report.** Lot 0 says "report, do not edit", but it also instructs installing Playwright if absent, and the build had to be run to state the before-state build status truthfully. No source file was modified.
- **Counted `40%` in `style.css:223` and `style.css:604` as false positives.** They are CSS gradient stops, not claims.
- **Counted `24h/24` in `bornes-publiques:40` and `:99` as false positives.** "Stations sécurisées 24h/24" and "bien éclairées 24h/24" describe continuous availability, not a response-time commitment. The brief forbids a response-time *figure*; these are not one.
- **Counted `application/json` in `main.js:186` as a false positive** for the "application" sweep.
- **Widened the claim sweep beyond the brief's literal strings.** The brief lists eight; the same defect classes appear ~53 times, including three strings it did not name: `IEC 62196`, `NF C 15-100`, and an "Installation en 24h" lead-time badge. The brief explicitly anticipates this ("If a claim string appears anywhere Lot 0 did not predict… log it and fix it"), so the wider set is in scope rather than a scope expansion.
- **Treated `securite/index.njk:4` (meta description) as in-scope.** It is a published claim even though it never renders as visible copy — precisely the "alt text, meta description, JSON-LD, OG tags" case the brief calls out.
- **Recorded the Sveltia `base_url` mismatch as a defect rather than fixing it in Lot 0.** `src/admin/config.yml` points at `auth.orionenergycmr.com`; `CLAUDE.md` mandates the shared `auth.wouree.com`. Lot 0 is report-only, and changing an auth host is a Lot 1 structural change. Logged as D-04.
- **Did not change `backend.branch: main` in the Sveltia config.** The CMS is correctly wired to production for the live site; repointing it is outside this branch's authority and would break the client's editing today.
- **Logged the `#25D366` WhatsApp green as compliant, not as a palette violation.** `CLAUDE.md` requires non-brand status/utility colours to sit outside the brand palette; a third-party channel colour on a third-party channel button is the intended case.

## Lot 1 — Content model and foundations

- **Put editorial content in `content/` at the repository root, outside `src/`.** Eleventy's input is `src`, so files there are never mistaken for templates: no stray routes, no `permalink: false` on every item, no `eleventyConfig.ignores` to maintain. The alternative — `src/_content/` with native Eleventy collections — needed per-directory data files and an ignore rule to stop 40-odd content files becoming 40-odd empty pages.
- **Named the loader `orion.js`, not `content.js`.** `content` is a reserved Eleventy data property (it holds a template's rendered body) and a global data file of that name aborts the build with a fatal error. Found by hitting it. Templates read `orion.claim`, `orion.product`, and so on.
- **Enforced governance in the loader rather than in templates.** `CLAUDE.md` requires enforcement in the template rather than by editorial discipline; dropping gated items at load is one level stronger, because a template cannot render what it was never handed. A typo in a template cannot leak an unapproved claim. Every drop is counted and printed at build time, so a disappearing item is visible rather than silent.
- **Made content validation fail the build, not warn.** A missing required field, a bad enum value, an `IEC` string in a product's certifications, a response-time figure in a form's confirmation message, or a universal-compatibility phrase on a GB/T product all abort the build with the file and the reason. A CMS that can write invalid content is a CMS that will; the guard has to be in the build, not in a reviewer's attention.
- **Allowed an `internal:<ref>` evidence scheme for claims about ORION itself, while requiring a public `http(s)` URL for `donnee_externe`.** The confirmed client data has no public source — its evidence is questionnaire response `ORION-20260809-4M59`, a record Digitaall holds. Forcing a fake URL would have been worse than naming the internal reference. External facts, which anyone can check, get no such latitude.
- **Kept one deliberately unapproved claim in the collection: `delai-de-reponse`.** The client's one-hour commitment is under review and must not be published. Recording it as `approved: false` traces the data without publishing it, and gives Lot 8 something concrete to assert the gate against.
- **Wired the i18n architecture but emit no `hreflang`.** The brief asks for an `/en/` twin per route with correct `hreflang`, and separately forbids writing English copy. Emitting `hreflang="en"` at a URL that 404s is a claim about the site the site cannot honour — the exact failure this project exists to correct. So the machinery is complete (locale registry, translation keys, URL derivation, per-page `alternates`, `lang`, canonical) and `en.built` is `false`; nothing is emitted for an unbuilt locale. Turning English on is one line in `src/_data/i18n.js` plus the pages: no template change, no permalink rewrite, no data migration.
- **Replaced `src/_data/site.json` with `src/_data/site.js` reading `content/site_settings/general.md`.** One editorial format across the whole model instead of a JSON blob shaped unlike everything else. `cities` is now derived from the `city` collection rather than duplicated, so coverage is stated once. Field names moved to snake_case; the three camelCase references (`formEndpoint`, `phoneClean`, `analyticsId`) all lived in `base.njk` and were updated.
- **Emptied `phone` and `phone_clean` rather than carrying the `+237 6XX XXX XXX` placeholder forward.** `site.has_phone` gates every `tel:` link, so the footer and `/contact/` render no phone block at all until a real number arrives. A visibly absent number is honest; a fake one that dials nowhere is not. Logged as P-01.
- **Migrated `faq.json` into 17 `faq_item` files, with the answer as the Markdown body.** Prose belongs in prose. The build's own validator caught the first attempt, which had `answer` as a required front-matter field.
- **Converted `trust`, `process`, `values` and `services` JSON from bare arrays to `{ key: [...] }` objects (D-06) instead of deleting the collections.** Their contents are riddled with claims Lot 2 must remove, but the shape had to match what the CMS writes before an editor could safely touch them. Five template loops updated.
- **Did not set `publish_mode: editorial_workflow`.** It would be a genuine safety gain — an approval step before anything reaches the live site — but it changes how the client edits their own site today and nobody asked for that. Recommended in the run report instead, for them to accept or decline.
- **Left `backend.branch: main` in the CMS config.** Repointing the client's live CMS at a build branch would break their editing today, and `main` is outside this branch's authority.
- **Seeded `partner` empty.** `CLAUDE.md` forbids naming the two known site hosts without written agreement. The collection and its `verified` gate exist; there is nothing in it.

## Lot 2 — Phase 0 remediation

- **Sent form posts as `text/plain` rather than `application/json`.** Apps Script does not answer `OPTIONS`, so a JSON content-type triggers a CORS preflight that fails before the request is made. `text/plain` is a "simple request" and skips the preflight; the body is still JSON. This is what makes `result.ok` readable at all — the previous `mode: 'no-cors'` made it unreadable by construction.
- **Made an unconfigured form fail visibly instead of silently.** The old code showed the success message and discarded the submission when no endpoint was set — which is the state the live site is in today. It now shows an error naming the problem and offers a WhatsApp link that reaches someone. A form that cannot submit must say so; thanking someone for a request nobody received is the same class of failure as an unevidenced claim.
- **Resolved CTA destinations through the `cta` collection rather than hardcoding 21 hrefs.** Fixing them in place would have left the same duplication that made them rot. A `ctaHref` filter means a destination changes in one file. The modal still opens on click; the href is the fallback beneath it.
- **Pointed the `partenaire` CTA at `/contact/` rather than at `/site-partenaire/`.** Lot 3 builds that page later in this same run, but if the run stopped at Lot 2 the link would 404 — worse than the dead `href="#"` it replaced. Lot 3 changes one content file and all four of its links follow.
- **Deleted the `-40 %` figure and restated the surviving stat rather than blanking a cell.** The two-cell stat row would otherwise have rendered with one empty half. The replacement claims nothing numeric.
- **Rewrote the two `/securite/` standards cards rather than deleting them.** Removing `IEC 61851` and `IEC 62196` would have left a "Normes" section with one card. They are replaced by CE, RoHS, and verified earthing — the last being the thing that actually fails in Cameroonian installations, and something ORION genuinely does.
- **Reviewed all 17 migrated FAQ answers, not only the ones the greps flagged.** Five more carried invented figures the discovery greps had no pattern for: a 2–5 year warranty, an 11 kW model not in the catalogue, "80 % in 30–60 minutes", a "1/5 of a tank" cost ratio, and payment terms nobody has agreed. The recharge-time and running-cost answers now give the reader the arithmetic instead of an average that would be nobody's actual number — which is both more honest and more useful.
- **Removed two "sous 48h" quote commitments.** The brief lists `Réponse sous 24h`; these were the same class of promise at a different number, and the discovery grep had no pattern for them.
- **Kept `24h/24` on the public-stations page.** "Stations sécurisées 24h/24" describes continuous availability, not a response-time commitment. Deleting it would have removed a true statement to satisfy a string match.
- **Stated GB/T as fact and announced no adaptation.** `/services/bornes-publiques/` claimed "Compatibilité universelle — connecteurs Type 2 et CCS", the opposite of what the hardware carries, and the FAQ claimed compatibility with every vehicle on the market. Both now name GB/T plainly and tell the reader to check their own inlet. Neither suggests an adapter or a workaround, because none is confirmed. Logged as pending a client decision, per the connector rule.
- **Disabled hidden modal fields, not just visually hidden them.** Found by the browser smoke test: the modal reuses one form for five configurations, and several hidden fields carry `required`. A hidden required field is invalid and not focusable, so the browser refuses to submit and cannot show the user why — the form does nothing when clicked. Disabling also keeps irrelevant fields out of the payload.
- **Pinned `lucide` to 0.469.0 (D-11).** `@latest` lets a supplier-side release break the icon layer of every page with no commit in this repository.
- **Put no `telephone` in the LocalBusiness schema.** There is no confirmed voice number. Inventing one for a search engine is the same offence as inventing one for a visitor. Likewise no `aggregateRating` and no `priceRange` — only the 7 kW residential band is confirmed, which is not a site-wide price range.
- **Used `sessionStorage` for attribution, not cookies.** No tracking identifier, no cross-site id, nothing that outlives the tab. It carries campaign parameters from the landing page to whichever form the visitor eventually reaches, which is all that is needed.
- **Built the event layer to work with no analytics id configured.** Events accumulate in `dataLayer` and go nowhere until an id is set, so instrumentation is written once and switched on later without touching the pages again.
